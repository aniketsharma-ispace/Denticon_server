Privacy Policy

Last updated: October 26, 2026

This Privacy Policy describes how Insurance Auditor Pro ("the Extension") handles information. The Extension is distributed for Google Chrome and Mozilla Firefox. By using the Extension, you agree to the practices described in this policy.

Summary: The Extension does not send your data to the developer or to any third party. Data is read from dental insurance portals you are already signed in to, held temporarily in your browser's local storage, and exported as a file to your own device.

1. What Data Does the Extension Access?

Insurance Auditor Pro is a tool for dental professionals. When explicitly triggered by the user, it reads the following from supported dental insurance portals that the user is already authenticated to:

  • Personally Identifiable Information (PII): Patient and responsible-party name, date of birth, email address, and phone number as displayed on the portal.
  • Health Information: Dental insurance plan details, coverage percentages, procedure codes and categories, frequency limitations, waiting periods, and benefit history as displayed on the portal.
  • Financial Information: Account balances, estimated insurance and patient portions, deductibles, and annual maximums as displayed on the portal.
  • Website Content: Text and page data from the supported portals listed in Section 6, required to extract the above.

The Extension does not read pages on any website outside the list in Section 6.

2. How Is Data Used?

  • Temporarily storing captured insurance data in the browser's extension storage while the user moves between portal pages and between portals.
  • Requesting additional benefit details from a portal's own API, using the session the user is already signed in with (see Section 4).
  • Compiling the result into a structured JSON file saved to the user's own device for audit and reconciliation purposes.

3. Data Storage & Retention

  • Data is stored only in the browser's local extension storage (storage.local) and session storage (storage.session) on the user's own machine.
  • Session storage is cleared automatically when the browser session ends or the portal tab is closed.
  • Local storage holds the current audit so it can be assembled across pages. It is cleared by the Extension during an audit run, replaced when the next audit begins, and removed entirely when the Extension is uninstalled.
  • Users may clear this data at any time by removing the Extension or clearing browser data for it.
  • No data is stored outside the user's browser and the files the user chooses to export.

4. Data Sharing & Transmission

The Extension sends network requests only to the insurance portals listed in Section 6, and only to the portal the user is actively working in. These requests carry the user's own existing signed-in session, and are the same requests the portal's own web interface makes. They are used to retrieve benefit details for the patient the user is already viewing.

The Extension does NOT:

  • Send any data to the developer, to any analytics service, or to any server operated by or on behalf of the developer.
  • Sell, rent, or transfer user data to any third party.
  • Use data for advertising, profiling, or any purpose unrelated to the Extension's insurance auditing function.
  • Use data to determine creditworthiness or for lending purposes.

5. Permissions Used

Each permission requested by the Extension and the specific reason it is required:

PermissionWhy it is needed
storage Holds the in-progress audit in the browser's own extension storage while the user moves between portal pages, and holds the current portal session reference. Nothing is written outside the browser.
activeTab Lets the Extension act on the portal tab the user has open at the moment they click the Extension's toolbar button.
tabs Reads the active tab's URL so the Extension can tell which supported portal is open and show the correct controls, sends scrape and export commands to that tab, and detects when a portal tab is closed so its stored session reference can be discarded.
scripting Runs the export routine on the supported portal page when the user clicks a button in the Extension popup.
webRequest Used read-only, and only on the Cigna dental benefits API host, to observe the authorization header on the request the user's own browser already sends while signed in. This lets the Extension request that same patient's benefits from Cigna's API on the user's behalf. The Extension does not block, modify, or redirect any request, and does not observe requests on any other site.

Host permissions are limited to the portals listed in Section 6 and are required for the Extension's content scripts to read insurance data from those portals.

7. Intended Users & Children's Privacy

The Extension is intended for use by dental professionals acting within their existing authorized access to these portals. It is not directed at individuals under the age of 13, and the developer does not knowingly collect data from children. Patient records handled through the Extension remain under the control of the dental practice that accesses them.

8. Your Responsibilities

The Extension is a tool operated by the user. Users are responsible for ensuring their use of it complies with their own obligations regarding patient information, including any applicable privacy and health-information regulations, and with the terms of the portals they access.
